# T06.3 — Representar validaciones de campos vacíos y formato de WhatsApp

| Elemento | Descripción |

| Estado | Implementación documentada; verificación funcional parcial |

### Historia de usuario

Como cliente, quiero registrar mi nombre y número de WhatsApp al realizar un pedido anticipado, para que el establecimiento pueda identificar mi compra y asociarla correctamente con mis datos.

## 2. Objetivo

Documentar las validaciones implementadas en AlInstant para evitar que el cliente continúe con el proceso de compra cuando ingrese campos vacíos o un número de WhatsApp con formato incorrecto.

Estas validaciones buscan garantizar que la información sea correcta antes de registrarla en el sistema.

## 3. Implementación de las validaciones

El sistema contempla validaciones tanto en el frontend como en el servidor Next.js.

### 3.1. Validaciones del frontend

El formulario React/Vite de `Sprint 1/Codigo/frontend/src/App.tsx` verifica los datos ingresados y deshabilita el avance mientras no sean válidos.

Entre las condiciones consideradas se encuentran:

- Nombre obligatorio.
- Nombre con una longitud válida.
- DNI obligatorio de ocho dígitos.
- Número de WhatsApp obligatorio.
- Número celular peruano con formato válido.
- Restricción para continuar cuando los datos no cumplen las condiciones.

### 3.2. Validaciones del backend

La API Route `POST /api/client/orders`, implementada en `app/api/client/orders/route.ts`, usa `parseCustomer` de `lib/client-checkout.ts` para validar nuevamente los datos antes de abrir la transacción. Los datos inválidos devuelven `422 INVALID_CUSTOMER`. No utiliza Express ni Zod.

### 3.3. Archivos relacionados

| Archivo | Función |
|---|---|
| `Sprint 1/Codigo/frontend/src/App.tsx` | Bloquea el avance local cuando DNI, nombre o WhatsApp son inválidos. |
| `lib/client-checkout.ts` | Centraliza `parseCustomer`, incluida la normalización. |
| `app/api/client/orders/route.ts` | Traduce el error de validación a la respuesta HTTP del checkout. |
| `Sprint 1/Testing/client-checkout.test.ts` | Prueba los formatos válidos e inválidos. |

## 6. Resultado de la tarea

Se documentó la implementación vigente de las validaciones de DNI, nombre y WhatsApp en el frontend y en la API Next.js. Las referencias y evidencias de Express/Zod se mantienen solo como trazabilidad del prototipo anterior.

Asimismo, se recopilaron evidencias del código responsable de procesar las validaciones y de dos escenarios relacionados con el ingreso de información incorrecta en el formulario.

La ejecución completa de los casos de prueba y la consolidación de sus resultados se desarrollarán en la tarea T06.5.

## 7. Conclusión

Las validaciones de los datos del cliente son necesarias para evitar registros incompletos o incorrectos durante el proceso de compra anticipada.

La implementación contempla controles en el formulario y en el servidor, permitiendo comprobar la información antes de almacenarla.

Con esta tarea se documentó el funcionamiento previsto de dichas validaciones y se reunieron evidencias para respaldar las pruebas del registro del cliente.
