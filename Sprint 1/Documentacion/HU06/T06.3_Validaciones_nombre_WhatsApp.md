# T06.3 — Representar validaciones de campos vacíos y formato de WhatsApp

## 1. Información general

| Elemento | Descripción |

| Sprint | Sprint 01 |
| Historia de usuario | HU-06 — Registrar datos del cliente |
| Tarea | T06.3 — Representar validaciones de campos vacíos y formato de WhatsApp |
| Estado | Implementación documentada; verificación funcional parcial |

### Historia de usuario

Como cliente, quiero registrar mi nombre y número de WhatsApp al realizar un pedido anticipado, para que el establecimiento pueda identificar mi compra y asociarla correctamente con mis datos.

## 2. Objetivo

Documentar las validaciones implementadas en AlInstant para evitar que el cliente continúe con el proceso de compra cuando ingrese campos vacíos o un número de WhatsApp con formato incorrecto.

Estas validaciones buscan garantizar que la información sea correcta antes de registrarla en el sistema.

## 3. Implementación de las validaciones

El sistema contempla validaciones tanto en el frontend como en el backend.

### 3.1. Validaciones del frontend

El formulario desarrollado con React y TypeScript verifica los datos ingresados y permite informar al cliente cuando existe algún problema.

Entre las condiciones consideradas se encuentran:

- Nombre obligatorio.
- Nombre con una longitud válida.
- Número de WhatsApp obligatorio.
- Número celular peruano con formato válido.
- Restricción para continuar cuando los datos no cumplen las condiciones.

### 3.2. Validaciones del backend

El backend utiliza Express y un esquema de validación con Zod para comprobar la información recibida.

En la versión actualizada del proyecto, las reglas se encuentran centralizadas en `shared/customer.ts`.

El endpoint `PATCH /api/me`, ubicado en `server/app.ts`, utiliza el esquema `customerInput` para validar los datos antes de actualizar la información del cliente.

Esto permite que el servidor también controle la información recibida, independientemente de las restricciones del formulario.

### 3.3. Archivos relacionados

| Archivo | Función |
|---|---|
| `shared/customer.ts` | Define las reglas de validación compartidas. |
| `src/customer.tsx` | Implementa las validaciones en el formulario. |
| `server/domain.ts` | Expone el esquema compartido al backend. |
| `server/app.ts` | Valida los datos recibidos mediante la API. |
