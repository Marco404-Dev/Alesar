## 2. Objetivo

Describir y comprobar la relación entre los datos de identificación del cliente (nombre y WhatsApp) y el pedido que realiza en AllInstant, a fin de permitir que el sistema identifique a quién pertenece cada compra.

## 3. Descripción de la solución

En el proyecto se utiliza **PostgreSQL** como base de datos y **Prisma** como herramienta de modelado y acceso a los datos. En el archivo `prisma/schema.prisma` se definen los modelos `Customer` y `Order`.

- **Customer:** almacena el identificador del cliente (`id`), su nombre (`name`) y su teléfono (`phone`).
- **Order:** registra la información del pedido y contiene `customerId`, `customerName` y `customerPhone`.
- El campo **`Order.customerId`** establece una relación con **`Customer.id`**, de manera que **un cliente puede tener varios pedidos y cada pedido corresponde a un cliente**.
- Los campos `customerName` y `customerPhone` también se almacenan en el pedido. Esto permite conservar los datos de identificación utilizados en esa compra.

## 5. Referencia al código de implementación

Archivo de referencia: `prisma/schema.prisma`.

```prisma
model Customer {
  id        String   @id @default(cuid())
  name      String   @default("")
  phone     String   @default("")
  createdAt DateTime @default(now())
  sessions  Session[]
  orders    Order[]
}
```

En el modelo `Order` aparecen las siguientes propiedades relacionadas con el cliente:

```prisma
  customerId    String
  customerName  String
  customerPhone String
  customer      Customer @relation(fields: [customerId], references: [id])
```

> Nota: El último bloque es un extracto del modelo `Order`, no su definición completa.

### Evidencia 3 — Consulta en PostgreSQL

**Qué colocar:** captura de una consulta ejecutada **después de crear un pedido de prueba**, donde se observe el pedido y los datos del cliente asociado. No inventar resultados.

Consulta de referencia para una base de datos PostgreSQL generada con Prisma, siempre que las tablas conserven sus nombres por defecto:

```sql
SELECT
    o."number" AS numero_pedido,
    o."customerId" AS id_cliente,
    c."name" AS nombre_cliente,
    c."phone" AS whatsapp_cliente,
    o."customerName" AS nombre_en_pedido,
    o."customerPhone" AS whatsapp_en_pedido,
    o."status" AS estado
FROM "Order" AS o
INNER JOIN "Customer" AS c
    ON o."customerId" = c."id"
ORDER BY o."createdAt" DESC
LIMIT 10;
```

**Resultado esperado:** la consulta devuelve, si existen pedidos registrados, filas con el identificador del cliente y sus datos asociados al pedido. Una consulta sin filas no demuestra que el registro funcione.
