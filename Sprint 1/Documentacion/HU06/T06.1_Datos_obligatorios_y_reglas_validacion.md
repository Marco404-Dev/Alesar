### Historia de usuario

Como cliente, quiero registrar mi nombre y número de WhatsApp al realizar un pedido anticipado, para que el establecimiento pueda identificar mi compra y asociarla correctamente con mis datos.

## 2. Objetivo

Definir y documentar los datos obligatorios que debe ingresar el cliente al realizar un pedido en AllInstant, estableciendo las reglas de validación necesarias para garantizar que la información sea correcta antes de continuar con el proceso de compra.

## 3. Datos obligatorios

El formulario de registro solicita dos campos principales:

| Campo | Tipo de dato | Regla de validación |
|---|---|---|
| Nombre | Texto | Obligatorio, entre 2 y 100 caracteres, eliminando espacios al inicio y al final. |
| WhatsApp | Texto numérico | Obligatorio, número celular peruano de 9 dígitos que comienza con 9. |

Estas validaciones permiten reducir errores al registrar los datos del cliente y facilitan su asociación con el pedido correspondiente.

## 4. Reglas de negocio

Se establecieron las siguientes reglas:

- **RN-06-01:** Ambos campos son obligatorios para continuar con el pedido.
- **RN-06-02:** El nombre debe cumplir con la longitud permitida y asociarse al cliente.
- **RN-06-03:** Se admite el prefijo internacional `+51`, normalizando el número al formato nacional.
- **RN-06-04:** Se eliminan espacios, guiones y paréntesis del número telefónico antes de validarlo.
- **RN-06-05:** El sistema no debe registrar pedidos con datos del cliente que no cumplan las validaciones.
- **RN-06-06:** Los avisos de WhatsApp se mantienen como una simulación; no se envían mensajes reales.

## 5. Criterios de aceptación

- [ ] Los campos de nombre y WhatsApp se identifican como obligatorios.
- [ ] El sistema acepta nombres que cumplen con la longitud permitida.
- [ ] El sistema rechaza nombres vacíos o inválidos.
- [ ] El sistema acepta números celulares peruanos válidos.
- [ ] El sistema rechaza números con formatos incorrectos.
- [ ] El backend impide registrar pedidos con información inválida.

**Nota:** Los criterios se mantienen pendientes hasta ejecutar y registrar las pruebas correspondientes.

## 6. Implementación técnica

El proyecto utiliza React y TypeScript en el frontend, Node.js y Express en el backend, además de PostgreSQL y Prisma para la persistencia de datos.

Los archivos relacionados con esta tarea son:

| Archivo | Función |
|---|---|
| `shared/customer.ts` | Define las reglas de validación compartidas para los datos del cliente. |
| `src/customer.tsx` | Implementa el formulario de nombre y WhatsApp. |
| `server/domain.ts` | Expone el esquema de validación compartido al backend. |
| `server/app.ts` | Aplica las validaciones en las operaciones del servidor. |

La utilización de reglas compartidas permite mantener un mismo criterio de validación en el frontend y backend.
