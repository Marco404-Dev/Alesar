### Historia de usuario

Como cliente, quiero registrar mi nombre y número de WhatsApp al realizar un pedido anticipado, para que el establecimiento pueda identificar mi compra y asociarla correctamente con mis datos.

## 2. Objetivo

Definir y documentar los datos obligatorios que debe ingresar el cliente al realizar un pedido en AlInstant, estableciendo las reglas de validación necesarias para garantizar que la información sea correcta antes de continuar con el proceso de compra.

## 3. Datos obligatorios

El checkout solicita tres campos obligatorios:

| Campo | Tipo de dato | Regla de validación |
|---|---|---|
| DNI | Texto numérico | Obligatorio, exactamente 8 dígitos. |
| Nombre | Texto | Obligatorio, entre 2 y 100 caracteres, eliminando espacios al inicio y al final. |
| WhatsApp | Texto numérico | Obligatorio, número celular peruano de 9 dígitos que comienza con 9. |

Estas validaciones permiten reducir errores al registrar los datos del cliente y facilitan su asociación con el pedido correspondiente.

## 4. Reglas de negocio

Se establecieron las siguientes reglas:

- **RN-06-01:** DNI, nombre y WhatsApp son obligatorios para continuar con el pedido.
- **RN-06-02:** El DNI debe contener exactamente ocho dígitos; el nombre se normaliza eliminando extremos y espacios repetidos, y debe medir entre 2 y 100 caracteres.
- **RN-06-03:** Se admite el prefijo internacional `+51`, normalizando WhatsApp al formato nacional de nueve dígitos que inicia en 9.
- **RN-06-04:** Se eliminan espacios y guiones de WhatsApp antes de validarlo.
- **RN-06-05:** El sistema no debe registrar pedidos con datos del cliente que no cumplan las validaciones.
- **RN-06-06:** Los avisos de WhatsApp se mantienen como una simulación; no se envían mensajes reales.

## 5. Criterios de aceptación

- [x] Los campos DNI, nombre y WhatsApp se identifican como obligatorios.
- [x] El sistema acepta valores válidos y normaliza nombre y WhatsApp.
- [x] El sistema rechaza DNI, nombre o WhatsApp inválidos.
- [x] La ruta del servidor impide registrar pedidos con información inválida.

## 6. Implementación técnica

La implementación vigente utiliza React/Vite y TypeScript en el cliente, una API Route de Next.js en el servidor y PostgreSQL mediante `pg`. No utiliza Express ni Prisma.

Los archivos relacionados con esta tarea son:

| Archivo | Función |
|---|---|
| `Sprint 1/Codigo/frontend/src/App.tsx` | Implementa los campos de DNI, nombre y WhatsApp y bloquea el avance local con datos inválidos. |
| `lib/client-checkout.ts` | Normaliza y valida datos en `parseCustomer`. |
| `app/api/client/orders/route.ts` | Vuelve a validar los datos en servidor antes de crear el pedido. |
| `Sprint 1/Testing/client-checkout.test.ts` | Cubre aceptación, normalización y rechazo de datos de cliente. |

La utilización de reglas compartidas permite mantener un mismo criterio de validación en el frontend y backend.
