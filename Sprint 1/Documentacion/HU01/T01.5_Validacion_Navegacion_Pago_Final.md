# T01.5 — Validación de navegación hacia el proceso de pago

**Proyecto:** AlInstant — ALESAR  
**Sprint:** 1  
**Historia de usuario:** HU-01 — Pedido anticipado para recojo  
**Estimación:** 2 horas  
**Tecnologías:** React, TypeScript, Vite y CSS

## Objetivo

Validar que el cliente pueda recorrer las pantallas de compra anticipada y llegar al inicio del proceso de pago, conservando la sede seleccionada, los productos, las cantidades y el total del pedido.

## Alcance

Se implementó una pantalla **simulada** de inicio de pago para comprobar la navegación. La HU-01 no realiza cobros ni registra pedidos en una base de datos.

## Flujo validado

Selección de sede → Catálogo → Carrito → Verificación final del pedido → Inicio del proceso de pago (simulado).

## Validaciones funcionales

| Caso | Validación | Resultado |
|---|---|---|
| V01 | Seleccionar San Martín de Porres o La Molina y acceder al catálogo | Conforme |
| V02 | Agregar productos, modificar cantidades y recalcular el total | Conforme |
| V03 | Impedir continuar con el carrito vacío | Conforme |
| V04 | Regresar al catálogo y conservar el pedido | Conforme |
| V05 | Mostrar la sede, los productos y el total en la verificación final | Conforme |
| V06 | Navegar desde «Continuar al pago» hacia la pantalla simulada | Conforme |
| V07 | Regresar desde la pantalla de pago sin perder información | Conforme |
| V08 | Comprobar la visualización en celular, tablet y computadora | Conforme |

## Ejemplo de comprobación de cálculo

- 3 × Lomo Saltado (S/ 12.00) = **S/ 36.00**.
- El resumen y la pantalla simulada de pago conservan el mismo total.

## Resultado

Se validó la navegación de la HU-01, desde la selección de sede hasta el inicio del proceso de pago simulado. Se comprobó la conservación de los productos, las cantidades y el total durante la navegación, así como la restricción para continuar con el carrito vacío.
