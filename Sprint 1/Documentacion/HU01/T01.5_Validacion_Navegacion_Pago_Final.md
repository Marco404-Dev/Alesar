# T01.5 — Validación de navegación hacia el proceso de pago

**Proyecto:** AllInstant — ALESAR  
**Sprint:** 1  
**Historia de usuario:** HU-01 — Pedido anticipado para recojo  
**Estimación:** 2 horas  
**Tecnologías:** React, TypeScript, Vite y CSS

## Objetivo
Validar que el cliente pueda recorrer las pantallas de compra anticipada y llegar al inicio del proceso de pago, manteniendo la sede elegida, los productos, las cantidades y el total.

## Alcance
Se implementó una pantalla **simulada** de inicio de pago para verificar la navegación. La HU-01 no procesa pagos ni registra pedidos en una base de datos; esas funcionalidades corresponden a otros desarrollos.

## Flujo validado
Selección de sede → Catálogo → Carrito → Verificación final del pedido → Inicio del proceso de pago (simulado).

## Validaciones funcionales

| Caso | Validación | Resultado |
|---|---|---|
| V01 | Selección de sede (San Martín de Porres o La Molina) y acceso al catálogo | Conforme, según comprobación manual |
| V02 | Agregar productos, modificar cantidades y recalcular el total | Conforme, según comprobación manual |
| V03 | Evitar continuar con el carrito vacío | Conforme. El sistema impide avanzar con el carrito vacío |
| V04 | Regresar al catálogo y conservar el pedido al continuar la compra | Conforme, según comprobación manual |
| V05 | Mostrar sede, productos y total en la verificación final | Conforme, según comprobación manual |
| V06 | Navegar desde «Continuar al pago» hasta la pantalla simulada | Conforme, según comprobación manual |
| V07 | Regresar desde la pantalla de pago sin perder información | Conforme, según comprobación manual |
| V08 | Comprobar las pantallas en celular, tablet y computadora | Conforme, según comprobación manual |

## Ejemplo de comprobación de cálculo
- 3 × Lomo Saltado (S/ 12.00) = **S/ 36.00**.
- La pantalla simulada muestra la sede, el producto, la cantidad y el mismo total.

## Resultado
Se comprobó la navegación principal de la HU-01 y la conservación de los datos del pedido entre pantallas. La pantalla final solo simula el inicio del pago. Falta registrar la prueba explícita del caso de carrito vacío antes de dar por completa toda la matriz de validación.
