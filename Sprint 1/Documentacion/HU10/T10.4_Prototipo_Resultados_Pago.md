### Historia de usuario

Como cliente, quiero pagar mi pedido mediante Yape o tarjeta desde la página web, para completar mi compra antes de llegar al establecimiento.

## 2. Objetivo

Representar mediante un prototipo las respuestas que recibirá el cliente después de intentar pagar su pedido en AllInstant.

Para esta tarea se consideran principalmente dos resultados: pago aprobado y pago rechazado. También se contempla el caso en el que la operación todavía no tiene una confirmación.

La idea es que el cliente pueda conocer el estado de su pago y que el sistema no confirme pedidos cuando la operación no haya sido aprobada.

## 3. Desarrollo del prototipo

El prototipo toma como referencia la pantalla de selección del medio de pago definida en la T10.3.

Una vez que el cliente revise el total de su compra y seleccione Yape o tarjeta, podrá continuar con el proceso de pago.

Durante esta etapa se plantea utilizar resultados simulados, sin realizar transacciones bancarias reales.

### 3.1. Escenario de pago aprobado

Cuando la operación sea aprobada, el sistema deberá mostrar una pantalla de confirmación.

Se consideran las siguientes acciones:

- Registrar el pago como aprobado.
- Confirmar el pedido del cliente.
- Asignar el estado inicial "Pedido recibido".
- Mostrar un mensaje indicando que la compra fue realizada correctamente.
- Permitir que el pedido confirmado pase a la lista de atención de la sede seleccionada.

**Mensaje propuesto:**

"Tu pago se realizó correctamente. Hemos recibido tu pedido y pronto comenzaremos a prepararlo."

### 3.2. Escenario de pago rechazado

Si la operación es rechazada, el sistema deberá informar al cliente que no fue posible completar el pago.

En este caso se consideran las siguientes condiciones:

- Mostrar un mensaje de pago rechazado.
- No confirmar el pedido.
- Evitar que el pedido pase a cocina o despacho.
- Permitir que el cliente vuelva a intentar el pago.
- Conservar el resumen de la compra para que no tenga que seleccionar nuevamente los productos.

**Mensaje propuesto:**

"No pudimos completar tu pago. Revisa los datos e inténtalo nuevamente."

### 3.3. Escenario de pago sin confirmación

También se contempla el caso en el que todavía no se recibe una respuesta definitiva de la operación.

El sistema deberá informar que el pago sigue sin confirmarse y mantener el pedido fuera de la lista de atención.

Este escenario es diferente al rechazo, porque todavía no se conoce el resultado final de la transacción.

**Mensaje propuesto:**

"Tu pago todavía no ha sido confirmado. Espera la actualización del estado antes de intentar otra operación."

En este caso no se deberá confirmar el pedido ni iniciar otro cobro automáticamente.

## 4. Comportamiento esperado del prototipo

| Escenario | Mensaje mostrado | Estado del pedido |
|---|---|---|
| Pago aprobado | Pago realizado correctamente | Pedido recibido |
| Pago rechazado | No se pudo completar el pago | Sin confirmar |
| Pago sin confirmación | Pago pendiente de confirmación | Sin confirmar |

El prototipo deberá mostrar una respuesta diferente para cada escenario.

Solo cuando el pago sea aprobado se podrá confirmar la compra y enviarla al proceso de atención.

## 9. Conclusión

Con esta tarea se estableció cómo deberá responder AllInstant después de intentar realizar un pago mediante Yape o tarjeta.

Se busca que el cliente reciba información clara sobre el resultado de su operación y que solamente los pedidos con pagos aprobados sean confirmados.

El siguiente paso será comprobar estos escenarios mediante pruebas, verificando que los pagos rechazados o sin confirmación no generen pedidos para cocina o despacho.
