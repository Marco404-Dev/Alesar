
# T10.5 — Validación del proceso de pago de pedidos

**Proyecto:** AllInstant — ALESAR  
**Sprint:** 1  
**Historia de usuario:** HU-10 — Pagar mi pedido desde la web  
**Tecnologías:** React, TypeScript, Vite y CSS  
**Estado:** Validaciones definidas; pruebas pendientes de ejecución

## Objetivo

Validar que el proceso de pago de AllInstant permita seleccionar Yape o tarjeta y que solamente los pagos aprobados puedan confirmar un pedido.

También se busca comprobar que los pagos rechazados o sin confirmación no generen pedidos para cocina y despacho.

## Alcance

Se plantea validar el proceso mediante pagos simulados, sin realizar transacciones bancarias reales.

Las pruebas consideran la selección del medio de pago, la respuesta del sistema y la confirmación del pedido según el resultado de la operación.

## Flujo por validar

Resumen del pedido → Selección de Yape o tarjeta → Procesamiento del pago (simulado) → Resultado de la operación → Confirmación o rechazo del pedido.

## Validaciones funcionales

| Caso | Validación | Resultado |
|---|---|---|
| V01 | Mostrar el monto total antes de continuar con el pago | Pendiente |
| V02 | Seleccionar Yape o tarjeta como medio de pago | Pendiente |
| V03 | Impedir continuar sin seleccionar un medio de pago | Pendiente |
| V04 | Simular un pago aprobado y confirmar el pedido | Pendiente |
| V05 | Simular un pago rechazado y evitar la confirmación | Pendiente |
| V06 | Mantener sin confirmar los pagos pendientes | Pendiente |
| V07 | Mostrar un mensaje según el resultado de la operación | Pendiente |
| V08 | Verificar que solo los pedidos aprobados pasen a cocina y despacho | Pendiente |

## Ejemplo de comprobación

Se considera un pedido con un monto total de S/ 36.00.

- Si el pago es aprobado, el pedido deberá confirmarse con el estado **Pedido recibido**.
- Si el pago es rechazado, el pedido no deberá confirmarse.
- Si el pago queda sin confirmación, el sistema deberá mantenerlo pendiente.
- El monto mostrado durante el pago deberá coincidir con el total del pedido.

## Resultado

Se definieron las validaciones necesarias para comprobar el comportamiento del proceso de pago de la HU-10.

Los casos consideran los pagos aprobados, rechazados y sin confirmación, además de las restricciones para evitar que pedidos sin pago aprobado pasen al personal de atención.
